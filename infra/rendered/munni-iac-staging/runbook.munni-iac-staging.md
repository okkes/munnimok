# First-time runbook — munni-iac-staging

Generated by `bootstrap --stack munni-iac-staging`. Work top to bottom;
every later deploy is automatic. Secrets minted this run: none.

> ⚠ Operator secrets still MISSING in GitHub Environment `iac-staging`:
> IAC_LOGTO_INFRA_M2M_ID, IAC_LOGTO_INFRA_M2M_SECRET, NAS_GHCR_PAT, NAS_GOCARDLESS_SECRET_ID, NAS_GOCARDLESS_SECRET_KEY, NAS_ADMIN_SUBS — bootstrap will not verify until they exist.

## 1. DNS + firewall (once per stack — the only host steps left manual)

Reverse-proxy rules are CODE now: the bootstrap's DSM module creates
them via SYNO.Core.AppPortal.ReverseProxy whenever SYNOLOGY_* creds
are in the environment (the IaC workflow injects them). Rules applied:
- munni-iac-test.okkes.synology.me → localhost:8295
- munni-iac-test-api.okkes.synology.me → localhost:8297
- munni-iac-test-admin.okkes.synology.me → localhost:8296

Still manual (probed by --verify, never scripted):
- DNS: the *.okkes.synology.me wildcard already covers these subdomains
  when using Synology DDNS; external registrars need the records.
- DSM firewall: allow 172.16.0.0/12 (docker bridge) in the access
  profile — Logto self-fetches its ADMIN_ENDPOINT through the host
  gateway — and RESTRICT munni-iac-test-admin.okkes.synology.me to LAN.

## 2. Deploy the containers

The rendered `docker-compose.munni-iac-staging.yml` + `.env.munni-iac-staging`
ship through the NAS bundle pipeline (new `munni-iac-staging` channel in
deploy-nas.yml — IAC4 wires this; until then copy the rendered pair to
`/volume1/docker/munni-iac-staging/` and `docker compose up -d`).

## 3. Logto apps

Nothing manual — the pair's OOBE happened on munni-iac-prod; re-running
bootstrap creates this stack's apps through the same infra credential.

## 4. GlitchTip DSNs (after first boot)

Open https://glitchtip-iac.okkes.synology.me → create org `munni-iac` + projects
(pwa/api/admin per stack) → store each DSN:
`gh secret set NAS_API_SENTRY_DSN --env iac-staging`,
`gh variable set VITE_GLITCHTIP_DSN --env iac-staging`,
`gh variable set VITE_GLITCHTIP_DSN_ADMIN --env iac-staging`.

## 5. Native apps (first upload is Apple/Google-mandated manual)

- Android: trigger `native-android.yml` against environment
  `iac-staging` (appId `app.munni.iac.dev`, label
  "munni iac dev", scheme `munni-iac-dev://`). Download
  the signed .aab artifact → Play Console → create app
  `app.munni.iac.dev` → upload to Internal testing → grant the CI
  service account. Every later upload is CI.
- iOS: App Store Connect → New App (bundle `app.munni.iac.dev`) →
  the workflow's TestFlight lane takes over from build 2.
- Store the Play signing SHA-256 back into the stack file if universal
  links are wanted on this pair.

## 6. Verify

`node infra/bootstrap.mjs --stack munni-iac-staging --verify` probes web,
api /health, logto well-known and glitchtip and prints anything still
unreachable with the exact fix.
