# First-time runbook — munni-iac-prod

Generated by `bootstrap --stack munni-iac-prod`. Work top to bottom;
every later deploy is automatic. Secrets minted this run: none.

> ⚠ Operator secrets still MISSING in GitHub Environment `iac-production`:
> IAC_LOGTO_INFRA_M2M_ID, IAC_LOGTO_INFRA_M2M_SECRET, NAS_GHCR_PAT, NAS_GOCARDLESS_SECRET_ID, NAS_GOCARDLESS_SECRET_KEY, NAS_ADMIN_SUBS — bootstrap will not verify until they exist.

## 1. DNS + DSM reverse proxy (once per stack)

Create reverse-proxy rules (Control Panel → Login Portal → Advanced →
Reverse Proxy), all sources HTTPS okkes.synology.me:443:

| Source host | Destination |
|---|---|
| munni-iac.okkes.synology.me | http://localhost:8290 |
| munni-iac-api.okkes.synology.me | http://localhost:8292 |
| munni-iac-admin.okkes.synology.me | http://localhost:8291 (RESTRICT TO LAN in the firewall) |
| logto-iac.okkes.synology.me | http://localhost:3101 |
| logto-iac-admin.okkes.synology.me | http://localhost:3102 (RESTRICT TO LAN) |
| glitchtip-iac.okkes.synology.me | http://localhost:8293 |

Firewall: allow 172.16.0.0/12 (docker bridge) in the access profile —
Logto self-fetches its ADMIN_ENDPOINT through the host gateway.

## 2. Deploy the containers

The rendered `docker-compose.munni-iac-prod.yml` + `.env.munni-iac-prod`
ship through the NAS bundle pipeline (new `munni-iac-prod` channel in
deploy-nas.yml — IAC4 wires this; until then copy the rendered pair to
`/volume1/docker/munni-iac-prod/` and `docker compose up -d`).

## 3. Logto OOBE (ONCE per pair — the single manual auth step)

1. Open https://logto-iac-admin.okkes.synology.me → create the admin user.
2. Applications → Create → Machine-to-machine → name it `infra`,
   assign the Logto Management API role (all permissions).
3. Store its credentials:
   `gh secret set IAC_LOGTO_INFRA_M2M_ID --env iac-production` and
   `gh secret set IAC_LOGTO_INFRA_M2M_SECRET --env iac-production`.
4. Re-run `bootstrap --stack munni-iac-prod` — the logto module now
   creates web/admin/native/m2m apps + the API resource as code and
   writes the ids back to the GitHub Environment.

## 4. GlitchTip DSNs (after first boot)

Open https://glitchtip-iac.okkes.synology.me → create org `munni-iac` + projects
(pwa/api/admin per stack) → store each DSN:
`gh secret set NAS_API_SENTRY_DSN --env iac-production`,
`gh variable set VITE_GLITCHTIP_DSN --env iac-production`,
`gh variable set VITE_GLITCHTIP_DSN_ADMIN --env iac-production`.

## 5. Native apps (first upload is Apple/Google-mandated manual)

- Android: trigger `native-android.yml` against environment
  `iac-production` (appId `app.munni.iac`, label
  "munni iac", scheme `munni-iac://`). Download
  the signed .aab artifact → Play Console → create app
  `app.munni.iac` → upload to Internal testing → grant the CI
  service account. Every later upload is CI.
- iOS: App Store Connect → New App (bundle `app.munni.iac`) →
  the workflow's TestFlight lane takes over from build 2.
- Store the Play signing SHA-256 back into the stack file if universal
  links are wanted on this pair.

## 6. Verify

`node infra/bootstrap.mjs --stack munni-iac-prod --verify` probes web,
api /health, logto well-known and glitchtip and prints anything still
unreachable with the exact fix.
