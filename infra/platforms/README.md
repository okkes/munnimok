# Platforms and environments — config as code

Everything the pipeline deploys is described here, generated by the setup
wizard (`infra/setup/index.html`) and read by the workflows. Secrets never
live in these files.

**Where it lives (#416, 2026-10-01).** The files are not committed. The wizard
keeps them on this computer (`infra/platforms/nas/` is git-ignored) and publishes
each platform as ONE repository variable, `MUNNI_PLATFORM_<ID>` — the platform file
and every environment file as one JSON document (`{ platform, envs, publishedAt }`)
— on every Save. Every workflow job materializes the files from the variable first
(`infra/ci/materialize.mjs`), so `loadStack` and the render read what they always
read. What a run applied is recorded on the stack's GitHub environment as
`MUNNI_APPLIED` (the config it ran with); the wizard's pending strip compares it
with what is saved here and says *Publish* when GitHub does not hold the save yet.
A cleanup publishes the variable without the environment; the platform card's
*Fetch config from GitHub* writes GitHub's copy onto another computer. `lcl`
keeps its platform file in the repository (a fixture without secrets) and is
published the same way when GitHub is connected, so the phone builds know its
environments.

```
infra/platforms/<platform>/platform.json      the platform: how it is reached and delivered
infra/platforms/<platform>/envs/<env>.json    one environment on that platform
```

Platforms: `lcl` (this computer, Docker Desktop, the wizard's helper runs
it), `nas` (Synology, deployed by GitHub Actions through the DSM File
Station API + a Task Scheduler poller), `rpi` (Raspberry Pi — reserved,
not implemented). Each platform runs ONE shared stack
(`munni-<platform>-shared`: GlitchTip, Vaultwarden, pgAdmin, the control
cockpit, valkey, OCR — and on `lcl` the family Caddy) and any number of
environment stacks (`munni-<platform>-<env>`: web, admin, api, its OWN
Logto and its OWN Postgres).

Naming: environment hosts are `munni-<env>-<platform>` (+ `-api`,
`-admin`, `-lab`, `-logto`, `-logto-admin`); shared hosts are
`<service>-<platform>` (`glitchtip-nas`, `vault-nas`, `pgadmin-nas`,
`control-nas`). On `nas` they sit under the platform's domain; on `lcl`
under `<lan-ip-dashed>.sslip.io` in LAN mode, else `localhost:<port>`.
Ports come from the environment's SLOT (stable across deletions): web
8380 + 100·slot, admin 8381 + …, api 8382 + …, connector 8387 + …,
lab 8388 + …, logto 3201 + 100·slot, logto admin 3202 + …; the shared
stack uses 8383 (glitchtip), 8384 (vault), 8385 (control), 8386 (pgadmin).

GitHub environments: `<platform>-shared` and `<platform>-<env>`. The
`nas` ones hold every secret its deploys need; the `lcl` ones only what
the native app builds need (GitHub builds the phones' apps for every
platform).

## platform.json

```json
{
  "platform": "nas",
  "label": "Synology NAS",
  "delivery": "synology",
  "domain": "${PLATFORM_DOMAIN}",
  "registry": "ghcr.io/okkes",
  "publishedPath": "/docker/munni-nas/published",
  "controlEnv": "prod",
  "branch": null
}
```

`domain` stays a placeholder in the public repo — the value is the
platform secret `PLATFORM_DOMAIN`. `publishedPath` is where bundles land
(File Station path); the live dir is its parent. `controlEnv` names the
environment whose API and Logto the control cockpit signs into (default:
the lowest slot). `agentEgress` says where the environments' pooled
browser agents' traffic leaves from (`{ "country": "NL", "kind":
"residential" }` by default — a home line; a rack says `"datacenter"`),
and the control planes believe it; the agents themselves are the
environments' (`agents`, below — #420). `branch` names the branch every run of this platform checks out
for its templates and tools; empty means each stack follows its image channel
(`latest` → master releases, `dev` → the dev branch), so a production
environment is never rendered with the dev branch's templates (#416).

## envs/<env>.json

```json
{
  "env": "prod",
  "slot": 0,
  "channel": "latest",
  "appChannel": "production",
  "label": "munni",
  "features": { "android": true, "ios": true, "push": true, "logos": true, "banking": ["gocardless"], "signin": ["google", "apple"], "pgadmin": true },
  "store": { "androidPackage": "app.munni.nas.prod", "iosBundleId": "app.munni.nas.prod" }
}
```

`channel` is the image tag the stack runs (`latest` = master releases,
`dev` = the dev branch). `appChannel` is what the app calls itself
(`production` | `staging`; default: production for `prod`, staging
otherwise). `store` ids default to `app.munni.<platform>.<env>`; the
deep-link scheme is always `munni-<env>-<platform>`.

`agents` (#420): `{ "pooled": 1, "concurrency": 2, "privateSlots": 0 }` —
how many pooled browser agents run beside the environment's control plane
(`connector-agent-<env>-<n>`, zero allowed), how many jobs each takes at
once, and how many hosted private slots (`connector-private-<env>-<n>`,
slice A2): one browser for one person each, in the household agent's
shape on munni's hardware, handed out from the admin portal when someone
asks. The wizard recommends the counts from the host's memory (a slot
takes one browser off the environment's share first); a change applies
with a Deploy, except the FIRST private slot, which mints the
environment's `CONNECTOR_PRIVATE_CODE` with a Bootstrap. Every
environment mints its own `CONNECTOR_FLEET_CODE`.

`features.connectors: true` adds the connector control plane (#367) to the
environment: one more container beside the api (`connector-<env>`, image
`munni-connector-api`) with its own database on the environment's
Postgres, the environment's Logto as its issuer, and a published host
`munni-<env>-<platform>-connector` on port 8387 + 100·slot that household
agents dial from outside (its API answers nobody without a machine token
or an agent's own token). The api gets the relay settings
(`Connectors:*`); the seal key, enrollment key and subject salt are minted
by the bootstrap, the api's machine app in Logto is written back by it.
